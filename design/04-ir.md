# 统一 IR 模块设计

## 结论

统一 IR 模块在 Common AST（02）与符号表（03）之上构建面向程序分析的语义中间表示。模块承接 02 保真产出的语法树，做语义规范化：desugar、显式化隐式控制流与隐式操作、规范化表达式，并把名称引用绑定到符号表符号、关联可求得的类型。统一 IR 是 Call Graph（05）、SSA（07）、指针分析（08）、污点分析（09）与符号执行（10）的共同底座。

统一 IR 与 common AST 的分工是本模块的根本边界：common AST 忠实记录源码语法形态，统一 IR 把语义等价的不同写法归一为单一规范形式。本文档同时固定 02 遗留的两个跨模块契约，见下节。

模块保持确定性与可回溯性：每个 IR 节点有稳定 `IRID`，并保留到 common AST 节点与源码区间的映射；无法规范化的语义生成带源码位置的诊断，不 panic、不静默丢弃。

├── module.go       # IRModule 聚合与查询入口

## 固定契约（回填自 02 遗留项）

**契约一：循环归一目标形式。** common AST 的 `ForStmt`、`WhileStmt`、`DoWhileStmt`、`ForEachStmt` 在 IR 中统一归一为单一 `IRLoop`，结构为“前置初始化 + 循环头（含条件求值位置）+ 循环体 + 迭代更新 + 规范化的跳出/继续目标”。四种源形态按如下规则映射：

- `WhileStmt`：条件在循环体前求值，无初始化与更新。
- `ForStmt`：初始化置于前置块，条件在体前，更新置于迭代更新块。
- `DoWhileStmt`：循环体先于条件执行一次，条件在体后求值，用规范化的“首次无条件进入”标志表达。
- `ForEachStmt`：desugar 为“取迭代器 + 循环头判断是否有下一项 + 取当前元素绑定到循环变量 + 循环体”的 `IRLoop`，迭代器获取方式记录在节点上。

`IRLoop` 必须保留 `origin` 字段标注源自哪种 AST 循环，保证可回溯且不丢失原始语义。

**契约二：对象构造识别归属。** common AST 只在有显式构造语法时产生 `NewExpr`（如 C++ `new`、Java `new`、Go 复合字面量构造），Python 的 `T()` 保留为 `CallExpr`。构造识别的最终归属在本模块：IR 在符号绑定阶段判定一个 `CallExpr` 是否为构造调用——当被调用名解析到类型符号或其构造器符号时，lower 为 `IRNew`；无法判定时保持 `IRCall` 并标注候选。由此五语言的对象构造在 IR 层获得统一的 `IRNew` 表达，而 AST 层不臆造语义。

## 目标

- 在 common AST 与符号表之上为五种语言构建统一 IR。
- 归一语义等价的循环、分支、赋值与成员访问等语法形态。
- 显式化隐式控制流（短路求值、异常边、隐式返回）与隐式操作（隐式转换、自增自减）。
- 将引用绑定到符号表符号，关联可求得的类型。
- 为每个 IR 节点分配稳定 `IRID` 并保留到 AST 与源码的映射。
- 保证等价语义在五语言下产生一致的 IR 结构。

## 非目标

- 不构建 Call Graph、控制流图之外的过程间结构。
- 不做完整类型推导，只做规范化所需的类型关联，缺失类型保留未知。
- 不做 SSA、指针分析或数据流，这些在下游模块。
- 不生成可执行代码或字节码。
- 不丢弃无法统一的语义，改用受控扩展保留。

## 使用场景

- 为 SSA 提供每个函数体的规范化语句与表达式序列。
- 为 Call Graph 提供带符号绑定的调用与构造节点。
- 为污点与符号执行提供归一后的控制流与数据操作。
- 从 IR 节点回溯到 common AST 节点与源码位置。

## 模块边界

### 统一 IR 负责

- common AST 到 IR 的 lowering 与语义归一。
- 显式化隐式语义并记录归一来源。
- 符号绑定与类型关联。
- 无法规范化语义的诊断与受控扩展保留。

### 统一 IR 不负责

- 作用域构建与名称解析，这些来自符号表。
- 类型继承层次、调用图、SSA、数据流。
- 宏展开与条件编译。

## 核心数据结构

```go
// IRID 是 IR 节点在当前分析任务中的稳定标识。
type IRID uint64

// IRKind 表示 IR 节点的语义种类。
type IRKind uint16

// IRNode 提供对 IR 节点的只读访问能力。
type IRNode interface {
    // ID 返回该 IR 节点的稳定标识。
    ID() IRID
    // Kind 返回该 IR 节点的语义种类。
    Kind() IRKind
    // Range 返回该节点对应的源码范围。
    Range() SourceRange
    // ASTNode 返回该 IR 节点归一自的 common AST 节点标识。
    ASTNode() NodeID
    // Symbol 返回该节点绑定的符号标识，未绑定时返回 false。
    Symbol() (SymbolID, bool)
    // Operands 返回该节点的操作数子节点，顺序稳定。
    Operands() []IRNode
}

// IRLoop 表示归一后的统一循环，四种源循环形态都映射到此结构。
type IRLoop struct {
    // id 是该循环节点的稳定标识。
    id IRID
    // preheader 是循环前置初始化块，无初始化时为空。
    preheader IRNode
    // cond 是循环条件求值节点，无条件循环时为空。
    cond IRNode
    // body 是循环体节点。
    body IRNode
    // update 是每次迭代后的更新块，无更新时为空。
    update IRNode
    // entryOnce 标记是否首次无条件进入，用于表达 do-while 语义。
    entryOnce bool
    // origin 记录该循环归一自的源 AST 循环种类，保证可回溯。
    origin LoopOrigin
    // rng 是该循环的源码范围。
    rng SourceRange
}

// IRNew 表示归一后的对象构造，五语言的显式与隐式构造都映射到此结构。
type IRNew struct {
    // id 是该构造节点的稳定标识。
    id IRID
    // typeSym 是被构造类型的符号标识。
    typeSym SymbolID
    // args 是构造实参节点，顺序稳定。
    args []IRNode
    // origin 记录该构造识别的来源，例如显式 new 或由 CallExpr 判定。
    origin NewOrigin
    // rng 是该构造的源码范围。
    rng SourceRange
}

// IRModule 聚合一个源文件或编译单元的 IR，供下游查询。
type IRModule interface {
    // FileID 返回该模块对应的文件标识。
    FileID() FileID
    // Functions 返回该模块内全部函数体 IR 的根节点。
    Functions() []IRNode
    // NodeByID 返回指定标识的 IR 节点，不存在时返回 false。
    NodeByID(id IRID) (IRNode, bool)
}
```

IR 种类至少覆盖：常量、名称引用、二元与一元运算、赋值、成员访问、下标、字段加载 `IRLoadField`、字段存储 `IRStoreField`、调用 `IRCall`、构造 `IRNew`、条件分支、统一循环 `IRLoop`、返回、跳转、异常边、类型转换和语言扩展包装。复合赋值 `a += b` 展开为 `a = a + b`；成员访问归一为统一节点，运算符差异（`.`/`->`）记为字段而非拆成不同节点，C++ 命名空间限定的 `::` 归为独立的命名空间访问节点；短路运算显式化为条件分支。字段读写统一表达为 `IRLoadField`/`IRStoreField`，作为 07 SSA 值来源与 08 指针分析别名解析的共同锚点。

## 对外接口

```go
// Lowerer 定义从 common AST 与符号表构建统一 IR 的能力。
type Lowerer interface {
    // Lower 消费一个源文件的 common AST 与项目符号表，产出该文件的 IR 模块与诊断。
    Lower(ctx context.Context, unit ast.CommonAST, symbols SymbolIndex) (IRModule, []Diagnostic, error)
}
```

接口约束：

- `Lower` 依赖已构建的符号表完成绑定；符号缺失时相关节点标注未绑定而非报错。
- 单个语义无法规范化通过 `Diagnostic` 表达，不作为 Go `error` 返回。
- Go `error` 仅用于系统性失败。
- 相同输入产生确定性的 `IRID` 分配与 IR 结构。
- 顶层入口 `BuildIR` 转发到 `Lowerer`，对批量文件语义等价于逐文件调用。

## 处理流程

1. 遍历 common AST，把每个函数或方法体作为 lowering 单元。
2. 按归一规则把 AST 节点 lower 为 IR 节点，循环归一为 `IRLoop`，分支、赋值、成员访问按契约与规范化规则处理。
3. 显式化短路求值、异常边与隐式返回等隐式控制流。
4. 在符号绑定阶段把引用绑定到符号，判定构造调用并 lower 为 `IRNew`。
5. 关联可求得的类型：只使用符号表已记录的声明类型与局部可直接推导的类型（字面量类型、赋值左值的声明类型、显式转换目标类型），不做跨函数返回类型推导、重载最终选择或泛型实例化求值，缺失类型一律保留未知状态，不臆造。
6. 为每个 IR 节点分配稳定 `IRID` 并记录到 AST 与源码的映射。
7. 对无法规范化的语义生成诊断并用受控扩展保留。
8. 输出 `IRModule` 与诊断。

## 错误处理

- 无法规范化的语义生成 `DiagnosticUnloweredSemantics`，保留源码范围与 AST 节点，继续处理其余部分。
- 符号未绑定的引用标注未绑定状态，不臆造符号。
- 类型无法求得时保留未知类型，不强行赋类型以免下游误判。
- 上游 AST 携带未映射节点时跳过并记录诊断，不中止整棵树。
- 内部不变量破坏且无法恢复时返回致命错误。

## 性能与资源限制

- IR 节点使用稳定标识关联，避免难以回收的引用环。
- 按需 lower，不为不参与分析的节点建立冗余 IR。
- 构建过程接受上下文取消信号。
- 对超深表达式与超深控制流嵌套设置可配置上限。
- 内置计时与 profile 埋点并可输出 IR 中间摘要，默认关闭。
- 性能基准在获得真实 fixture 后确定。

## 安全考虑

- 所有输入 AST、符号与类型信息均视为不可信数据。
- 不执行、编译或加载被分析项目代码。
- 对 IR 规模爆炸与超深归一递归设置资源边界。
- 诊断不包含与当前分析无关的环境敏感信息。

## 测试设计

- 单元测试覆盖五种语言的 lowering、归一、符号绑定与类型关联。
- 契约验证：四种源循环均归一为 `IRLoop` 且 `origin` 正确；`DoWhileStmt` 的 `entryOnce` 正确；`ForEachStmt` 的迭代器 desugar 正确。
- 契约验证：显式 `new` 与由 `CallExpr` 判定的构造均 lower 为 `IRNew`，无法判定时保持 `IRCall`。
- 归一验证：复合赋值展开、短路显式化、成员访问统一。
- 跨语言等价性：同一语义在五语言下产生结构一致的 IR。
- 负例：不产生无依据的符号绑定或类型关联。
- 边界：空函数体、深层嵌套、异常控制流与匿名函数。
- 回归：每个已修复归一缺陷对应独立 fixture。
- 确定性：相同输入产生一致 IR 与 `IRID`。

误报率按文件统计：产生错误归一、错误绑定或非预期诊断的合法文件数除以合法文件总数。最低标准为五种语言均有正报、总体及分语言误报率低于 30%。

## 验收标准

- 五种语言均能在 common AST 与符号表之上构建统一 IR。
- 契约一循环归一与契约二构造识别在测试中得到验证。
- 复合赋值展开、短路显式化、成员访问统一等归一规则通过测试。
- 跨语言等价性测试对每个语义分组断言 IR 结构一致。
- 无法规范化语义有诊断且不 panic、不静默丢弃。
- 五种语言均有有效正报，误报率低于 30%。
- `go test`、`go test -race`、静态检查与构建全部通过。
